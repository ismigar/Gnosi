# Knowledge Graph Architecture

> ID: `KNOWLEDGE-GRAPH-2026-08-01`
> Status: active

## Objective

Build every graph projection directly from current Gnosi domain data. The
Notion-era exported graph pipeline is retired. No generated graph file is a
source of truth.

## Sources of truth

- Markdown pages and their frontmatter are the content source.
- `BD/vault_db_registry.json` defines table schemas and relation fields.
- Stable page IDs identify Gnosi pages independently of filenames.
- `.gnosi/llm_wiki_suggestions.json` is the Brain proposal queue.
- Contacts remain a separate management-domain source when the global graph
  deliberately includes them.

`vault_pages.json`, `vault_graph.json`, and root-level `suggestions.json` are
not part of the current architecture. `OUT_JSON` and `OUT_GRAPH` path aliases
must not be used.

## Construction flow

The backend builds one in-memory structural topology from the current vault
snapshot and registry. It then derives explicit projections:

- the `/api/graph` transport response for the global and embedded graph;
- graph metrics used by virtual fields;
- the optional semantic-proposal overlay read directly from the Brain queue.

The HTTP response is JSON because it is the frontend transport contract. It
is not an intermediate persisted artifact.

## Topology rules

- Body wikilinks and schema relations retain their provenance and semantic
  direction.
- Stable-ID body links generated by Gnosi resolve to the page with that ID.
  They must not create an unresolved placeholder merely because the Markdown
  filename is human-readable.
- Only genuinely missing targets become `unresolved` nodes.
- Filtering a table is a view over the same vault, not a separate Obsidian
  vault. Do not manufacture scoped unresolved nodes for resolved targets that
  happen to be outside the current filter.
- Semantic suggestions are a scored overlay. They do not affect structural
  degree, pathfinding, isolation, or layout.
- Graph metrics exclude semantic suggestions and unresolved placeholders.

## Layout and interaction

The frontend owns layout because it knows the visible filtered subgraph. The
backend does not calculate or persist coordinates. This removes the redundant
igraph layout and `graph_layout_cache.json`.

Hover identity must follow the current geometry. Any layout or camera
transition invalidates the active hover before nodes move; rendering must not
continue to display Sigma's stale internal hover while the application hover
has been cleared.

## Caching

Caches live only under local data, are rebuildable, and never travel with the
vault. A cache may accelerate the page/link index or the final response, but it
must not introduce another graph representation or another source of truth.

Graph response invalidation occurs when indexed content, registry schema, or
the Brain proposal queue changes. No scheduler task writes a graph mirror.

## Retired pipeline

Remove the Notion-era generation chain and its catalog entries:

- `suggest_connections.py` enriched export;
- `filter_graph.py`;
- `json_to_sigma.py`;
- `augment_clusters.py` and its `content_cache.json` graph mutation;
- graph-only style and validation helpers with no remaining consumers.

The `suggest_connections` scheduler remains, but it invokes the canonical
Brain maintenance service directly.

## Verification

- The repository has no runtime references to `OUT_JSON`, `OUT_GRAPH`,
  `vault_pages.json`, `vault_graph.json`, or root-level `suggestions.json` for
  graph construction.
- Brain queue changes appear on the next `/api/graph` request without a mirror.
- Stable-ID wikilinks resolve to real pages and genuine missing links remain
  unresolved.
- Virtual graph fields derive from the same structural topology as the graph
  service, not from a persisted export.
- Backend graph tests, frontend graph tests, lint, build, and browser QA pass.

# QA Verification Protocol (Antigravity Protocol)

This is the mandatory security protocol to be followed after any modification to the Frontend or Backend that affects the UI.

> [!NOTE]
> **Memory Distinction**:
> 1. **Developer Memory** (System Skills and Directives): Located in Root `docs/` and `pipeline/skills/`. Standardized in **English**. These are strategic foundations.
> 2. **Bot Memory** (Gnosi Assistant): Located in `monorepo/apps/gnosi/backend/agent/instructions/`. Maintained in **Catalan/Spanish** for persona.
>    - **Agent Tools** (`backend/agent/generated_tools/`): Tactical, dynamic tools generated by the AI assistant. These follow Bot Memory instructions but should be promoted to System Skills if they become core capabilities.

## Objective
To ensure that no change sent to the user causes a "white screen," reference errors (undefined variables), or compilation failures.

## Mandatory Steps

### 1. Syntax and Compilation Verification
Before any `notify_user`:
- **Run `npm run build`**: You must attach the result or confirm that it finished with `Exit code: 0`. This detects forgotten imports and type/syntax errors that Vite might miss in fast dev mode.
- **Variable Grep**: If code has been removed, perform a `grep` to ensure no part of the JSX still references deleted variables.

### 2. Runtime Verification (Browser)
Compiling is not enough. You must test it:
- **Open `localhost:5173/vault`** (or the corresponding URL) using the `browser_subagent`.
- **Critical Actions**:
    - Load the home page.
    - Click an entry in the Sidebar (open page).
    - Open a Table/Database.
    - **Verify No Native Dialogs**: Ensure that no action triggers `window.confirm` or `window.alert`. Use custom modals instead.
- **Screenshot**: Take a screenshot of port 5173 to visually confirm that the UI is present and functions without native dialog interference.

### 3. Memory Consolidation (Crucial)
Before closing the task, ensure that technical knowledge has traveled to the correct place:
- **Staging Cleanup**: Has the temporary directive in `docs/dev_memory/directives/` been deleted if the task is stable?
- **Skill Update**: Has all information (UUIDs, mappings, CLI) been integrated into the `SKILL.md` of the corresponding `pipeline/skills/` folder?
- **Pointers**: If the directive in `docs/` is kept for architectural reasons, does it clearly point to the `Skill` for technical details?
- **Language Standard**: Are All new `SKILL.md` and `directives/*.md` files written in **English**? This is mandatory for technical standardization.

### 4. Tracking in `task.md`
All development tasks must include:
- `[ ] Verify integrity with npm run build`
- `[ ] Visual and functionality validation in the browser`
- `[ ] Consolidate staging memory into the corresponding Skill`

## Mandatory Self-Criticism
If a change passes this protocol and still fails on the user's side, the specific error must be documented here to reinforce the protocol (e.g., "Add click test in modals").

---
**Note for the Agent**: Violation of this protocol is considered a critical failure in task delivery.

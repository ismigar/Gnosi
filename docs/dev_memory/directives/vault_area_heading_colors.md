# Directive: Colored headings on Area pages

## Objective

Every page in the Areas table uses a fixed background color for each heading
section because all Area pages share one structure. This is visual only and
must not modify stored Markdown.

## Heading-to-color mapping

| Semantic heading | Color |
|---|---|
| Education | blue |
| Professional experience | pink |
| Competencies | brown |
| Developed | green |
| To develop | red |
| Contribution to purpose | yellow |
| Resources | gray |
| Projects | purple |
| Notes and excerpts | orange |

Matching accepts configured Catalan and Spanish heading aliases as persisted
content data. <!-- @language-example -->

## Implementation

- `areaHeadingColors.js` provides `normalizeHeadingText`, which removes
  wikilinks, accents, and punctuation, and `areaHeadingColorKey`, which
  performs prefix matching.
- In `BlockEditor.jsx`, `isAreaPage` resolves `metadata.table_id` to a table
  whose normalized name matches the Areas table.
- An effect injects `<style data-gnosi-area-headings>` rules indexed by each
  stable block `data-id`. It recursively walks `editor.document`, including
  column children, and recalculates on `editor.onChange`.
- `index.css` defines light and dark `--area-*` variables.

## Restrictions

- **Do not mutate ProseMirror DOM nodes.** ProseMirror detects external
  `setAttribute` or `classList` changes, redraws the node, removes the change,
  and can enter a roughly 46-redraw-per-second loop. Embedded `gnosi_view`
  nodes amplify the problem.
- **Do not use ProseMirror decorations.** BlockNote React node views ignore
  external decoration attributes and classes.
- **Do not use the block's native `backgroundColor`.** The Markdown mapper
  serializes it as an inline-styled `<div>`, polluting stored Markdown.
- Inject CSS indexed by the stable `data-id` generated by ProseMirror and
  escape identifiers with `CSS.escape`. Styling derived from the model avoids
  DOM mutation and redraw loops.
